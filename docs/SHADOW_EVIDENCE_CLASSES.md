# Shadow evidence classes

P10. A shadow position carries the evidence class of the runs that produced it,
and the classes are **never aggregated**. A structural shadow and an
effect-verified one are not two of the same thing; adding them gives a number
that describes neither.

```
STRUCTURAL_ONLY       an exact buildable buy and sell existed
JIT_EFFECT_VALID      both legs SIMULATED_EFFECT_OK under just-in-time state
OFFLINE_REPRODUCIBLE  both legs effect-verified from a frozen snapshot
CONFIRMATORY          additionally preregistered, on a clean commit
```

The class is **derived** from the simulation jobs behind the position's own two
legs, not asserted by whatever opened it. A shadow cannot be a better class than
the runs that produced it.

Generated by `pnpm shadow:status` into `artifacts/shadow-status.json`.

## Two findings that are not about the strategy

**The realizable portfolio took nothing.** Every one of the 1,079 shadows
records a portfolio refusal, and both reasons are halts:

```
983  weekly_loss_halt
 96  daily_loss_halt
```

The portfolio has been halted for the entire window. So there is no
portfolio-versus-shadow comparison to make, and any that was attempted would be
comparing a book that traded against a book that was switched off.

This is exactly what the shadow books exist to reveal. Without them the corpus
would show no positions and no reason, and the absence would read as "no
signals" rather than "the engine was halted".

**89% of shadow marks are unpriced.** 22,379 of 25,085 marks have no executable
value. Most are marks on positions whose route no longer builds — the 4XX sell
observations — rather than marks the scheduler skipped. Combined with the mark backlog (169 due against a capacity of 4, worst
lag ~1,020 s), the mark series is not currently dense enough to support an exit
rule, and it must not be read as one.

An unpriced mark is recorded and drives nothing. A mark that is not written is
an observation that never existed; a null read as a stop trigger would exit
every position the moment the builder had a bad minute.

## Entry

A shadow opens structurally after an exact buildable buy **and** sell. A
simulated-development shadow additionally requires both legs
`SIMULATED_EFFECT_OK`.

Every eligible episode opens fixed alpha and canary shadows **whether the
portfolio accepts or refuses**. That ordering is load-bearing: opening them only
on refusal put exactly the signals the portfolio rejected into the books, so
comparing shadow performance to portfolio performance compared the trades we
turned down against the trades we took.

## Marks

One mark observation is shared between books when the mint, token amount, family
and context bucket are identical. Two books at the same notional acquire the
same tokens, so they share; two books at different notionals acquire different
amounts and must not.

The shared row is labelled by what it is (`shadow_entry`,
`shadow_entry_roundtrip`), never by whichever book asked first — a row labelled
`alpha_shadow_entry` that both books reference is a lie to whoever reads the
corpus later.

Every decision-bearing mark is same-family.

## Exit

A shadow closes only on a later same-family, effect-valid observation **for its
own evidence class**. If no executable observation exists the shadow is
`EXIT_BLOCKED`: the tokens are still held, the rent is still locked, and the
exposure is still counted.

## Scheduling

When the backlog exceeds the frozen SLA the scheduler stops opening new shadows
and reports the skipped episodes. It does not silently stretch the cadence — a
mark series whose interval quietly widened under load is a series whose gaps
correlate with exactly the volatility that caused the load.
