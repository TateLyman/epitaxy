# Capability matrix — what can be simulated, by route shape

P5. One failed offline parity run on a stable pair through one AMM does not
establish that Pump routes cannot be simulated. It establishes that *that route*
could not be.

Treating a single venue's failure as a property of the simulator holds the whole
project hostage to the least tractable AMM in the sample, which is backwards:
the venues worth proving first are the ones the strategy actually trades.

Generated by `pnpm capability:matrix` into `artifacts/capability-matrix.json`.

## The fingerprint

```
route labels
programs the transaction actually invokes
token programs (Token vs Token-2022)
lookup table structure, bucketed
simulator feature set
```

The programs come from the **exact transaction blob**, which names the program
each instruction invokes. Not from the static account key list: a v0 message
carries the pools, vaults, mints and ATAs of the specific trade alongside the
programs, so hashing the key list gives one fingerprint per token. That was the
first version, and it turned 1,899 Pump observations into 1,899 unproven venues,
where nothing could ever accumulate evidence.

Lookup tables are bucketed `none` / `one` / `many`. One table versus two is a
structural difference in address resolution; seven versus eight is not.

## Supported evidence class

Every fingerprint is currently `STRUCTURAL_ONLY`, for one reason:

> every simulation of this fingerprint predates the leg-shaped request; those
> jobs measured the instrument

### The ceiling on Pump

Measured 2026-08-13: a live `Pump.fun Amm` route **passes JIT** (160,895 units,
exact 20,000,000 debit, real fees) and its **offline replay returns
`SIMULATION_UNKNOWN`** — six program ELFs cannot be restored on the request
path. See `docs/OFFLINE_REPLAY_BLOCKER.md`.

So Pump is capped at `JIT_EFFECT_VALID` however many effect-verified runs it
accumulates, and `CONFIRMATORY` is unreachable for it. The stable SOL→USDC pair
replays with 0 bps compute drift, so the offline mechanism itself is sound — it
is the six-program restore that fails, and a single stable-pair failure must
never be read as "offline replay does not work".

A fingerprint advances only on its own evidence:

- `JIT_EFFECT_VALID` — at least one `SIMULATED_EFFECT_OK` under JIT
- `OFFLINE_REPRODUCIBLE` — offline replay reproduced it, with no offline failures
- `CONFIRMATORY` — additionally a preregistered context and a clean commit

A Pump-only valid development window may begin while every other venue remains
structural-only. That is the point of stratifying.
