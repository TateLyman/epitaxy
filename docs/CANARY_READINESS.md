# Canary readiness

P18. Machine-generated by `pnpm readiness` into `artifacts/readiness.json`.
Nothing here starts anything. Funding a wallet and running `pnpm canary` is a
human act, and `.claude/hooks/guard.mjs` blocks the assistant from both.

## Current verdict

```
NOT_READY

confirmatory positions   0
valid development        0
```

Every economic gate fails, because there is nothing to evaluate. That is the
correct output and not a defect in the gate.

## What the previous gate did

`canaryEvidenceGates()` counted completed positions whose legs carried
`simulation = 'SIMULATED_OK'`, with clean commits and matching families. It
never asked what those positions **earned**.

A strategy that lost ten percent on every trade, consistently, with impeccable
provenance, satisfied it after 200 trades. `tests/unit/readiness.test.ts` builds
exactly that corpus and asserts the new gate refuses it.

It also accepted development JIT rows, which is the deeper error: a JIT run
fetches its own state from a moving chain, so the same transaction run twice is
two experiments.

## A confirmatory position

Inner joins, all of them. A position missing any clause does not partially
qualify.

```
both legs observed, same family, buy then sell
both policies PASS on both legs
both legs simulation_effect = SIMULATED_EFFECT_OK
both simulation jobs confirmatory = 1
both jobs validity = VALID_CONFIRMATORY
both jobs simulated_effect_ok = 1
both jobs account_coverage_ok = 1
raw payload retained on both legs
context on a clean (non-dirty) commit
position closed with a zero token balance
```

## The gates

Every one fails on insufficient data. Not "unknown", not "skipped" — a gate that
abstains when the sample is thin abstains exactly when the decision is most
dangerous.

| gate | requires |
|---|---|
| `sample.validCompletedPositions` | ≥ 200 confirmatory positions |
| `sample.calendarDays` | ≥ 21 days |
| `pnl.netPositive` | net > 0 |
| `pnl.expectedLogGrowth` | > 0 |
| `pnl.lowerConfidenceBound` | 95% lower bound on log growth > 0 |
| `pnl.profitFactor` | ≥ 1.25 |
| `risk.maxDrawdown` | ≤ 2,000 bps |
| `risk.catastrophicIncidence` | ≤ 2% total-loss trades |
| `robustness.recent50` | most recent 50 net positive |
| `robustness.exTop1/3/5/10` | positive without the best 1, 3, 5, 10 trades |
| `robustness.exBestDay` | positive without the best day |
| `robustness.exBestFiveMints` | positive without the best five mints |
| `concentration.noTradeOverTenPercent` | no trade > 10% of positive PnL |
| `concentration.noDayOverTwentyFivePercent` | no day > 25% of positive PnL |
| `stress.doubleCosts` | positive at 2× costs |
| `evidence.zeroReplayDivergence` | exactly 0 |
| `evidence.zeroUnresolvedReconciliation` | exactly 0 |
| `lifecycle.noBlockedExits` | exactly 0 |
| `evidence.stableSimulatorFingerprint` | exactly 1 distinct binary |
| `shadow.canarySizePositive` | canary-size shadow book net positive |

## Frozen thresholds

`CANARY_GATES` in `packages/research/src/readiness.ts`, pinned by test. A
threshold changed after looking at the corpus goes in
`docs/MULTIPLE_TESTING_LEDGER.csv` **before** the change lands, with the sample
it was chosen on.

**Do not weaken a failed gate.** A threshold moved to make a run possible is not
evidence about the strategy; it is evidence about whoever moved it.

## Benchmarks

Recorded in the artifact alongside the strategy result: no trade, hold SOL,
canary-size shadow. The random-eligible-entry and hard-gates-only baselines
require a sample to draw from and are not computable at zero positions.
