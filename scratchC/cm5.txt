P12: the commands mean their names, or they refuse

Five commands were aliases for other scripts. `pnpm rate:budget-v2` ran the
trajectory status; `pnpm reject:panel-v2` ran the same thing; `pnpm wss:status`
ran the direct-signal status; `pnpm landed:parity-v2` ran a NON-landed parity
script; `pnpm exploration:status` ran the cohort status.

An alias is worse than a missing command. A missing command is noticed the first
time somebody runs it. An alias produces well-formatted output about something
else, exits zero, gets pasted into a status document, and becomes evidence for a
capability that was never built. That is the same defect class as a proof
artifact standing in for a database.

Each now names the exact missing prerequisite and exits non-zero. Not "coming
soon": `landed:parity-v2` says that no direct PumpSwap swap has ever been landed
by this system because nothing here has signed or submitted, and that the
command cannot mean its name before a canary. `reject:panel-v2` says that
`reject_tracking` records THAT a token was rejected and not the state it was
rejected on, and that a panel scored from state fetched later is a different
experiment. An unknown command name is itself refused with exit 2, so the stub
cannot quietly absorb a typo.

`pnpm trajectory:status` now reads the database and has no code path that can
read a file. Not "it currently reports zero", which a caller could change --
there is no readFileSync, no existsSync and no JSON.parse in it. Proof artifacts
are counted as zero explicitly rather than by omission, because silence is
indistinguishable from having forgotten them. The old position-oriented status
keeps its own name as `development:status`: it answers a real question, just not
this one, and deleting it would lose the answer.

Two scripts were writing artifacts/trajectory-status.json, which breaks P12's
own rule. The last one to run decided what the file meant and neither said so.
The database status owns that name; the wider evidence generator writes
artifacts/evidence-status.json.

The corpus as the database has it: 43 trajectories, 15 settled, 5 frozen account
plans, and 8 paths whose five horizons were all taken on time. The daemon is now
producing timely 60-minute marks -- 11 of 15 rather than 0 of 4.
